# 极速浏览器 Windows 外壳

C++20 + Win32 + 官方 WebView2 SDK。标签条、工具栏、书签栏用 Direct2D 自绘，地址栏是系统 EDIT 控件；进程一启动先出窗口首帧，WebView2 环境与之并行创建，首个标签页画出后再预建一个隐藏的备用控件。书签和会话在后台暂存加载，首帧不等它们读盘，就绪后由界面线程一次接手。

## 构建

只走 GitHub Actions（`.github/workflows/build.yml`，windows-latest + MSVC）。WebView2 SDK 从 nuget.org 下载并校验 SHA256，加载器静态链接，CRT 静态链接，不需要 VC++ 运行库和 WebView2Loader.dll。

产物 `jisu-browser-win-x64-<提交>`：`jisu-browser/`（`jisu-browser.exe` + `ntp/` + `jisu-media.exe` + `media/`，即完整运行包，整个目录放到任意位置即可运行）、`symbols/jisu-browser.pdb`、`SHA256SUMS.txt`、`ci-smoke.json`（CI 机器上的一次冒烟时间线）。

图标由 `res/make-icon.mjs` 生成（`node res/make-icon.mjs` 重写 `res/app.ico`）。

门禁是 `ctest`（标签布局、真实绘制、书签与标签保护，以及会话恢复、弹窗拦截、标签拖拽、应用窗口这几个带窗口的测试）。在正在使用的机器上本地复现带窗口的测试，用 `tools/run-on-hidden-desktop.ps1` 把整条进程链（测试程序、浏览器、WebView2 子进程）放进一个从不显示的私有桌面：屏幕和任务栏上什么都不出现，也抢不到键盘焦点。

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-on-hidden-desktop.ps1 -OutputFile out.txt -CommandLine "powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\session-guard-test.ps1 -Exe <jisu-browser.exe>"
```

退出码就是被测命令的退出码，超时（`-TimeoutSeconds`，默认 300）会结束被测进程并返回 124；`-OutputFile` 收集命令的标准输出和错误输出（隐藏进程没有控制台）。

## 运行

`jisu-browser.exe [网址] [选项]`

同一用户数据目录只开一个日常主实例：再次启动（双击图标、别的程序打开链接）会把网址交给已开的窗口新开标签，然后退出；主实例还在冷启动时最多等 10 秒，不另开一个。带 `--no-activate` 的转发不抢焦点：有网址开在后台标签，没有网址只确认浏览器在运行（不多开空白页、不闪任务栏）。主实例卡住不响应时仍开一个能用的窗口，但它不开智能体桥、不装托盘、不写会话。

窗口位置、大小与最大化状态在关闭时记下，下次启动沿用（那块显示器不在了就用默认位置）；应用窗口按 app-id 分别记。崩溃、被结束、关机或系统更新重启后，下次启动恢复当时开着的标签（按窗口分组，各窗口当时的当前标签马上加载，其余点到时才加载）；正常关闭最后一个窗口默认下次从新标签页开始；可在 `jisu://settings` 勾选「启动时继续上次浏览」。最近25次标签/整窗关闭事件可在重启后按顺序重开，保留位置、固定、静音及整窗当前页；最多4MiB，淘汰按整组进行。日常窗口的 WebView2 内核进程退出或建不起来时自动重建并按原网址恢复标签（0.5 秒起退避，封顶 30 秒）；单个页面的渲染进程崩溃时自动重新加载一次，一分钟内再崩改为说明页。

独立应用窗口：`jisu-browser.exe --app http://127.0.0.1:30141/ --app-id pi-web --app-title "Pi Web" --app-icon "<Pi图标.ico>" --no-activate`。原生标题栏，无标签条、地址栏、书签栏；同一 app-id 重复打开复用应用窗口且不重置当前对话，与日常窗口分别关闭、分别显示任务栏身份。复用本机原资料目录，不复制登录态；应用不领取智能体标签、不增设托盘、不改日常扩展和书签。弹出链接交给日常极速窗口。网页内核建不起来、卡住超过 15 秒或共享内核进程退出时，窗口中央显示原因并自动重建（3 秒起退避，封顶 30 秒）；重复打开时若网页控件不在也立即重建。页面里的链接直接交给同一资料目录的日常窗口：用户点击的链接把日常窗口带到前面，脚本自己弹出的只开后台标签。安装脚本把程序标为中完整性，从管理员 shell 启动也与 Pi（Medium）共用同一内核进程。

| 选项 | 作用 |
|---|---|
| `--udf <目录>` | 用户数据目录，默认 `%LOCALAPPDATA%\JisuBrowser\User Data`（书签、设置也在这里） |
| `--agent-config <文件>` | 智能体桥配置，默认 `%LOCALAPPDATA%\JisuBrowser\agent-bridge.json`，文件不存在则不开桥 |
| `--no-agent` | 不开智能体桥 |
| `--inprivate` | 独立进程和正式InPrivate Profile，不开桥或扩展，不写外壳历史/会话/设置/下载记录 |
| `--metrics <文件>` | 写启动时间线 JSON（各时间点为距进程创建的毫秒数）；测量运行默认不开智能体桥、不导入书签 |
| `--exit-after-metrics` | 写完时间线即退出 |
| `--no-activate` | 显示窗口但不激活 |
| `--background` | 后台启动，不显示窗口（隐含 `--no-activate`）：进程、托盘、智能体桥照常工作，智能体页面在屏幕外宿主里执行；用户再次打开浏览器、点托盘或智能体请求交接时才显示窗口（此时才恢复会话、套用上次位置）。给自动化为智能体桥拉起浏览器用 |
| `--bounds x,y,w,h` | 窗口位置与大小（物理像素） |
| `--rt sw\|hw` | Direct2D 软件 / 硬件渲染目标，默认 sw（硬件路径建 D3D 设备太慢，首帧过不了 70ms） |
| `--warm-d3d 0\|1` | 后台线程提前建一个 D3D 设备（软件为 WARP，硬件为显卡）；默认软件预热、硬件不预热 |
| `--env early\|late` | WebView2 环境在首帧前 / 首帧后发起，默认 early |
| `--ntp folder\|inline` | 新标签页走随包 `ntp/` 目录 / 内置字符串，默认 folder |
| `--no-spare` | 不预建备用控件 |
| `--tracking-prevention 0\|1` | WebView2 跟踪防护，默认 1 |
| `--browser-args "<参数>"` | 传给内核的附加参数 |
| `--preheat <秒>` | 不显示窗口，只持有内核进程（模拟开机预热） |
| `--single-argument <网址或路径>` | 之后的全部原文是一个网址/文件（默认浏览器登记用），不再解析成选项，构造的链接夹带不了 `--browser-args` 等参数 |

快捷键：Ctrl+T 新标签，Ctrl+Shift+T 重新打开关闭的标签，Ctrl+W 关闭，Ctrl+Tab / Ctrl+PageDown 下一个、Ctrl+Shift+Tab / Ctrl+PageUp 上一个，Ctrl+1…8 第几个标签、Ctrl+9 最后一个，Ctrl+L / Alt+D 地址栏，F6 在内容、地址与原生工具栏间循环，F5 / Ctrl+R 刷新，Ctrl+Shift+R / Shift+F5 / Ctrl+F5 跳过缓存刷新，Alt+← / Alt+→ 后退前进，Ctrl+D 添加 / 编辑书签，Ctrl+Shift+B 书签栏，Ctrl+Shift+O 书签管理器；F11 真全屏，Esc 退出。地址栏里 Alt+Enter 在新标签页打开，Ctrl+Enter 把单个词补成 `www.….com`，Ctrl+Backspace 删除前一个词；右键菜单有「粘贴并转到」，多行文字粘进来自动接成一行。输入「3.14」这类数字走搜索，四段 IPv4、`[::1]` 这类 IPv6、本地路径（资源管理器打开 .html）按网址打开。网页视频／标准 Fullscreen API 进入时隐藏标签条、地址栏和书签栏，窗口覆盖当前显示器（含任务栏区域）；退出恢复原窗口位置与最大化状态。后台标签的全屏请求不改变用户窗口，切换／关闭全屏标签或导航时退出网页全屏。

工具栏最右的菜单：新建标签页、重新打开关闭的标签页、书签管理器、显示书签栏、导入书签、扩展管理、历史记录（Ctrl+H）、极速播放器（Ctrl+Shift+M）、设为默认浏览器（在当前用户下以 `--single-argument %1` 登记后打开系统「默认应用」页，由用户自己选）、关于。

标签右键：在右侧新建、重新加载、复制标签页、固定（不被「自动关旧标签」关掉，排在最左边）、静音、关闭、关闭其他、关闭右侧、重新打开关闭的标签页；批量关闭不碰固定标签和智能体标签。标签、工具栏图标和书签栏项都有悬停提示（标签显示完整标题与网址）。出声的标签显示扬声器，点一下静音；加载中的页面显示圆弧，与智能体执行中的实心点区分。用鼠标连续点关闭时剩下的标签先保持原宽，下一个关闭钮正好落在光标下，鼠标离开标签条再展开。新建标签默认排在当前标签右边（固定组之后）；链接、window.open 打开的标签排在打开者右边；Ctrl+点击、中键及右键「在新标签页中打开」在后台打开，Ctrl+Shift 保留前台语义；前后台决定使用按下时的有限快照，不采集输入文字，快照不授予弹窗或权限；缺快照时保守后台；切换标签后键盘焦点直接进网页（新标签页给地址栏）。

弹出窗口：WebView2 关掉了 Edge 的弹窗拦截，外壳按 `IsUserInitiated` 拦下网页没经用户点击就弹的窗口（弹窗广告、跳转劫持），地址栏右侧出现提示钮，点开可逐个打开、全部打开或「始终允许」该网站（存进 `jisu-settings.json` 的 `popupAllow`）；用户点击打开的、智能体页面弹出的照常。网页（含脚本跳转、弹窗、重定向）不能打开内部页面（新标签页、书签、历史、扩展管理、播放器），前进后退、刷新与智能体自己的自动化不受影响；脚本打开的窗口里网页调用 `window.close()` 时关掉该标签。

标签条同时承担窗口拖动、双击最大化和最小化／最大化／关闭，不再单独显示重复的系统标题栏。标签默认宽 220 DIP、高 45 DIP（标签条 50 DIP），选中标签通过反向圆角与工具栏连接；标签多时等比例压缩，不遮住新建标签或窗口按钮。外壳固定采用浅蓝灰标签条、白色选中标签和工具栏，不受 Windows 深色应用模式覆盖；新标签页、书签、历史、扩展管理这些内部页面同样固定浅色（与网页默认底色一致，不再先白后黑闪一下）；网页自身的配色仍由网页决定。网页盖住内容区时，悬停重绘只画顶部的标签条与工具栏。

日常实例运行期间常驻 Windows 托盘图标（系统可能收进右下角 `^`）：悬停显示版本、提交与「运行中」，单击恢复窗口，右键可打开浏览器、新建标签页或「彻底退出」。主菜单也有「彻底退出」；它与窗口 `×` 均正常关闭所有标签、扩展弹层和智能体桥，不是隐藏到托盘。退出后主动移除托盘图标；Explorer 重启后自动重新注册。测量与预热运行不创建托盘图标。

## 书签

与 Chromium 的 `Bookmarks` 文件同一格式，存放在用户数据目录下，其他 Chromium 系浏览器可以直接读。保存保留 date_last_used、meta_info、未知字段和未知根/子节点；导入按网址去重，只接收 http(s)。

- 地址框右端星标 / Ctrl+D：弹出收藏窗口，可改名称与网址、选择任意文件夹、当场新建子文件夹；记住上次保存位置。再次点击星标进入编辑，可移动位置或移除。取消不会创建书签或文件夹。
- 书签栏：点网址打开（Ctrl+点击、中键为新标签），点文件夹弹出菜单（文件夹里有两个以上网址时可「全部打开」），右键编辑 / 删除，放不下的收进「»」。按住拖动可排序，拖到文件夹中间并松开即可移入；高亮框表示移入，竖线表示插入，Esc 或拖出书签栏取消。
- 书签管理器（`jisu://bookmarks`）：文件夹树、搜索、添加、重命名、编辑网址、删除、从本机 Quark / Thorium / Chrome / Edge 等导入、导入与导出 Netscape HTML（含 Firefox 导出）。HTML 导入只收 http(s) 网址，按已有网址去重，单次最多 10,000 个网址、8MB 文件。编辑窗口也能选择保存位置、新建文件夹；拖到列表中的文件夹或左侧目录即可移入，拖到网址行前可排序。不允许把文件夹拖进自己或自己的子文件夹。支持多选后批量移动/删除，单批最多 1000 项并整体校验；「撤销」恢复上一步完整快照（本次进程内，最多20步/16MB，单份快照不超过8MB）。
- 不在首次启动自动扫描或导入其他浏览器；仅由用户在管理器主动选择。HTML/Chromium 导入在后台解析、校验、去重与合并，版本冲突重新基于最新快照合并，主线程原子交换，不覆盖同期编辑。
- 标签页、书签栏和管理器显示网站图标：优先用本机缓存（存在与否记在内存里，重绘不再查盘），访问页面后通过 WebView2 更新（内容没变不重写，写盘在后台线程）；WIC校验、缩放和像素解码均在后台，界面仅上传已解码像素，最多缓存512份64px像素（约8MiB）。不为缺图标的书签发HTTP请求或解析其DNS，未访问站点显示默认图标。图标缓存目录只在书签管理页打开期间映射成 `favicons.jisu.example`，普通网站探测不到本机访问、收藏过哪些站点。
- 书签改动合并 400ms 后在后台写盘，保存前轮转 `Bookmarks.backup-1` 至 `backup-3` 三代；读不了的书签文件在被覆盖前另存为 `Bookmarks.unreadable-<时间>`。书签栏开着但还没有书签时显示一句添加提示；书签栏空白处右键可加入当前网页、新建文件夹、隐藏书签栏；书签右键可「复制网址」。文件夹菜单的子菜单展开时才填内容、解码图标。

## 历史记录

`Ctrl+H`、菜单「历史记录」或 `jisu://history`。按时间分组，搜索标题/网址、分页、逐条删除、按站点/时段删除和清空；范围删除仅处理外壳历史，内核缓存另在设置清理。积压不再按2048条静默丢弃，连续同址访问合并保留频次，删除/清空保持顺序屏障；保留 90 天、最多 20,000 条。只从本版本开始记录普通标签成功导航和 SPA 路由，不导入其他浏览器的历史，不记录智能体后台标签、扩展/内部页、文件地址、带账号密码的 URL；历史和会话过滤 access_token 等敏感参数；code 仅在 state 或 OAuth/回调路径上下文中视为认证材料，普通业务 code 保留，其余正常参数不整串删掉。数据在本机资料目录 `History.json`，后台懒加载、合批原子写盘，不进入启动关键路径，也不同步到另一台机器。

## 下载与设置（0.5.1）

- `Ctrl+J` / 菜单 / `jisu://downloads`：查看下载进度、平均速度，暂停、继续、取消、重试，打开文件和所在文件夹。记录在本机 `Downloads.json`，最多保留 500 个已结束任务；重启后未完成任务标为中断，需要重新请求，不假装可以跨重启续传。含认证参数、blob URL 不提供重试。
- 自动回收保护下载源；手动关闭源标签后下载继续，管理器仍跟踪。最后一个窗口关闭或彻底退出前确认是否中断下载。智能体标签及其弹出页默认拒绝下载，避免在用户看不到的地方静默落盘。下载记录和登录资料不做跨机同步。应用窗口仍使用内核下载浮层，记录为 `Downloads-app-<app-id>.json`，暂未与日常列表合并。
- `jisu://settings`：搜索引擎（Bing / Google / 百度）、继续上次浏览、普通标签上限、下载目录、每次询问保存位置、撤销弹窗允许、查看并逐条撤销站点权限、清除浏览数据。保存提示只代表请求提交，后台保存失败会报告。
- 菜单另提供新建窗口、页面查找、打印、缩放/重置、开发者工具和内核任务管理器；缩放按站点来源保存，菜单显示真实倍率。拥挤时通过菜单「标签列表」选择标签，原生菜单可滚动。
- 写入失败保留最新数据并每秒重试，标题和内部页显示未保存状态，存储恢复后清除提示；外壳自身的崩溃最小记录位于资料目录 `Crash.log`，只含异常、模块偏移和版本，不生成内存转储。
- 地址栏下拉联想来自本机历史、书签和当前窗口已开标签；历史保留访问与手输频次参与排序。上下键选择、Enter 打开、Esc 收起；ASCII 域名前缀可内联补全，输入法组合及删除不补全。不向搜索服务发送输入或获取联网热词建议。

## 无痕、安全与原生可访问性

- `Ctrl+Shift+N` / 菜单 / `--inprivate`：新建独立私有窗口，使用正式 InPrivate 控制器并回读验证；不允许失败后退回普通 Profile。不复制登录材料，不记录外壳历史、会话、设置、下载列表或崩溃日志；关闭密码保存、自动填充、扩展和Cookie守卫。私有Cookie由内核内存隔离。书签/设置修改仅本次有效；主动下载仍保留文件，必须在用户正看的窗口询问保存；外部播放器不可用以免保存续播足迹。无痕不是系统/网络隐身，不隐藏管理员、系统或对端网站日志。
- `Ctrl+F/P/+/-/0/U/S`、F12 对应查找、打印、缩放/重置、源码、保存及开发者工具；`Ctrl+Shift+Delete` 打开清理设置，`Alt+Home` 回新标签页。隐藏智能体禁用内核原生快捷键和右键窗口，人工接管后恢复。
- 站点按钮/主菜单显示内核连接状态、只读证书和权限入口，不仅凭https字样显示安全锁；证书查看禁止安装及属性修改。data脚本和危险edge/chrome/about调试地址在SDK调用之前拦截，命令行、转发、旧会话及直接CDP导航同一口径；仅保留只读version/gpu/credits页。
- 自绘标签、工具栏、书签及窗口按钮提供标准MSAA与Windows UIA映射，保留原生EDIT/网页Document。F6、Tab、方向键、回车及空格可达，键盘焦点有可见边框；跨线程动作校验窗口实例号。
- 标签、选中地址可复制拖入书签栏，外部OLE只收有界http(s)链接/文本，不读文件拖放或全局剪贴板，不接受源移动副作用。
- 网页非持久通知沿用WebView2默认UI，受网站权限和Windows通知策略约束；隐藏智能体及无痕不展示此类通知。此规则不宣称覆盖普通Profile既有Service Worker的系统持久通知，真实Windows送达需单独实测。

## 极速播放器

- 菜单「极速播放器」/ `Ctrl+Shift+M` 交接当前网页的可用媒体直链；`jisu://player` 可打开本地文件或 HTTP(S) 直链。画面嵌在标签页内，独立 `jisu-media.exe` 进程使用 libmpv + FFmpeg + libass，关闭播放器标签后释放。首次使用前不创建媒体进程、不加载解码库，不对所有网页安装视频扫描器。
- D3D11 / `auto-safe` 硬解优先，不支持的编码由 FFmpeg 软件回退；H.264、HEVC、AV1、VP9 等是否硬解由硬件/驱动/格式决定，界面显示实际解码方式、编码、尺寸、丢帧与缓冲，不把软件回退称为硬解。
- 全屏/Esc、置顶小窗、0.5–4 倍速、精确拖动、逐帧、章节、截图到系统「图片」、画面比例、多音轨、外挂/内封字幕、第二字幕、音频/字幕延迟、去隔行；本地文件/稳定直链按哈希保存续播位置（本机 `PlayerResume.json`，不保存原始地址）；HDR 通过引擎色调映射呈现。Anime4K 着色器超分可选，默认关闭，持续丢帧时自动关闭，不与网页 NijiLucid 同时处理同一画面。
- 清番额外提供「极速播放」按钮、线路、上一集/下一集、连播、片头片尾、原网页观看进度回写、失败及连续 20 秒不推进时换线；需清番页面带 `jisu` 集成标记。原网页暂停并销毁 HLS 解码器，避免双路播放。普通页面不承诺这些站点专属操作。
- 不复制或导出 Cookie、网站凭据，不绕过 DRM/付费。没有可交接 URL 的 blob/MSE 流、需登录头/特殊来源头的站点保留网页原播放器；不把一个视频引擎称为“全站兼容”。播放错误只影响独立媒体进程。
- 完整包因媒体引擎和着色器增加磁盘/下载体积，原先 18MB 小包口径不再适用于完整媒体包。没有播放时不常驻媒体资源；播放、软件解码、超分仍会和网页/游戏共享 CPU/GPU/显存，不能承诺零影响。依赖版本/hash/许可证见 `THIRD-PARTY.md` 和运行包 `media/media-provenance.json`。

## 指定扩展与密码

`node tools/import-profile-assets.mjs --apply` 只处理本机能找到的 **Anime4K WebExtension、Auto Close Old Tabs、Authenticator** 程序文件，并导入本机网站图标缓存。扩展源码、账号、验证码种子、保险库和扩展存储不随浏览器发布；第三方程序不进仓库。

- 扩展通过 WebView2 的正式扩展 API 加载；已启用的扩展默认显示在地址栏右侧，悬停显示名称，点击在按钮下方打开独立弹层，再点一次、Esc 或点击外部关闭；不占用网页标签，不借用智能体标签。
- 「扩展程序」拼图按钮列出全部扩展，可打开、固定到工具栏／取消固定、进入设置或管理；管理页也有固定开关。固定状态写入本机 `extensions.json` 的 `pinned`，重启保留；取消固定不等于停用，停用的扩展不显示按钮。加载成功不代表所有 Chrome API 都兼容。
- Auto Close Old Tabs 的界面沿用原扩展，普通标签关闭由外壳原生适配：默认上限 10 个，按最近使用时间关闭最久未用的非当前普通标签（独立于标签 id，使用时间随会话保存；同资料所有窗口共用上限），保护当前页、固定标签、智能体租用标签、智能体页面弹出的标签和扩展页面。上限可在扩展「打开」里改为 1–99。扩展在首个页面加载完后才开始装（最多等 2 秒），不和首屏抢资源；关掉后台标签不打断地址栏输入。
- 安装清单写在用户资料目录的 `extensions.json`；指定 `removeUnlisted: true` 后，启动时会通过正式 API 移除未列出的扩展，结果在 `extensions-status.json` 与 `extensions-cleanup.json`。
- 开启 WebView2 原生密码保存和自动填充。但 SDK 没有跨浏览器密码导入接口；不会解密或直接搬运 `Login Data`、Cookie、登录会话或身份验证器种子。已有账号要在极速里登录；Authenticator 的保险库迁移需由用户通过其正式导入流程完成。

## Cookie 守卫

Chromium 内核对每个站点（eTLD+1）最多留 180 个 cookie，满了一次按最久没用的清掉 30 个，不分登录与否。网页模型桥每开一个临时对话会留下 `conv_key_<uuid>`、`history_off_<uuid>` 两个持久 cookie，累积到 180 就会把登录 cookie 一起挤掉。外壳因此自己守着：

- 日常实例内核就绪 20 秒后查第一次，之后每 5 分钟用 WebView2 的 CookieManager 取全部 cookie，按站点（eTLD+1，内置常见两段式后缀）计数；单站超过 `maxPerSite`（默认 20）就回收**最早的带 ID 的一次性 cookie**，直到不超或没有可回收的。
- 「带 ID」= 名字里有 UUID、16 位以上十六进制或 8 位以上纯数字，同类至少 3 个不同 ID 才算累积；同一个 ID 的全部 cookie 作为一个单元一起回收。**固定名字的 cookie（登录、偏好、风控）一个不动**，名字含 session/token/auth/login/passport/jwt/csrf/sso/credential/secret 的不动，会话 cookie 不动，有成员不符合条件的单元整体不动；最新的 `keepUnits`（默认 10）个单元一定保留，正在进行的对话要用。
- WebView2 不提供 cookie 的创建时间，「最早」用过期时间近似：同一类 cookie 寿命相同，先过期的就是最早建的。
- 因为基础 cookie 不动，上限是触发线、不是硬顶：chatgpt.com 自带约 31 个基础 cookie，稳态是 31 + 最新 10 个对话 × 2 ≈ 51。其余站点没有累积型 cookie，实际不受影响（2026-11-05 本机 609 个 cookie 实测只有 chatgpt.com 会被回收）。
- 每轮最多删 500 个，余下留给下一轮；应用窗口（`--app`）、测量和预热运行不启用。

配置 `<用户数据目录>cookie-guard.json`（没有就用默认值，每轮重读，改了不用重启）：`{"enabled":true,"dryRun":false,"maxPerSite":20,"keepUnits":10,"intervalSeconds":300}`；`dryRun` 只算不删，`maxPerSite` 为 0 或 `enabled` 为 false 即关闭。每轮结果写 `<用户数据目录>cookie-guard-status.json`（站点计数、计划数、实际回收数、累计回收数，不含 cookie 名称或值）。策略是纯逻辑的 `src/cookie_policy.h`，用例在 `tests/cookie-policy-test.cpp`。

## 智能体桥（CDP）

Pi 的 `browser` 工具走 Playwright MCP 的扩展模式：MCP 起一个本机 relay，经本机 broker（`127.0.0.1:18773`）发连接邀请，由浏览器里的扩展连上 relay 并用 `chrome.debugger` 转发 CDP。极速浏览器在外壳里原生实现扩展这一侧（`src/agent_bridge.cpp`），协议与 Pi 改版扩展一致，Pi 侧不用改：

- 轮询 broker 取邀请，校验配对令牌、协议版本与 relay 地址（只接受本机）。
- 从标签池租一个智能体标签（没有空闲的就新建一个），连上 relay，宣布标签并握手；断开后标签与页面留在池里，下一条连接接着用。用户正在看的标签不会被租用。
- 每条连接用 `Target.attachToTarget` 单开一个 CDP 会话，断开时 detach：Playwright 开过的域、注入的脚本随会话清掉（WebView2 自带的默认会话不随连接结束）。
- 与 Pi 扩展相同的单标签约束：拒绝新建 / 关闭标签；`Target.activateTarget` 一律忽略。
- 省电：执行命令时智能体标签在屏幕外宿主窗口里可见（WebView2 隐藏的控件不出帧，截图和 rAF 会卡住）；命令间隙超过 `graceMs` 就关掉焦点模拟并隐藏，页面定时器随即被节流，再过 `pageFreezeMs` 冻结。实测动画重页单核占用：可见 47%、隐藏但保留焦点模拟 15%、隐藏并关焦点模拟 0.2%。
- 唤醒后先等页面出一帧（rAF → setTimeout 0，最多 300ms）再转发命令，给积下的页面更新一个处理机会，降低读到旧内容的风险。这不是「页面已完成更新」的保证：冻结会暂停定时器与客户端逻辑，依赖这些逻辑的轮询、流式回答或后台任务可能延迟；要求持续运行时，把 `pageFreezeMs` 和 `freezeMs` 都设为 0。用户正在看的标签不冻结。
- **平时的 CDP 操作不开窗口**：智能体标签不在标签条里，页面一直在屏幕外宿主里执行；浏览器若是智能体拉起的（`--background`），连主窗口都不显示。只有智能体明确调用 `page.bringToFront()`（Pi 的 browser `action=handoff`，用于必须由人操作的登录、验证码、确认）时，这个页面才从池里搬进标签条、显示窗口并置前（后台进程默认没有前台权限，借当前前台线程的输入队列置前，被系统拒绝时任务栏闪烁）。交接期间租约不变，智能体可以继续观察页面；租约结束时用户正看着这个页面就归他（变成普通标签，不会在他眼前消失），否则退回池里。`agent-bridge.json` 的 `showTabs: true` 恢复旧行为（智能体标签像后台标签一样列在标签条里，带一个圈，点开可看）。它们的脚本弹框按 Playwright 默认处理（离开页面确认放行，其余取消），权限请求拒绝。

配置 `agent-bridge.json`（不存在就不开桥）：

```json
{
  "broker": "http://127.0.0.1:18774",
  "tokenFile": "<Pi 数据目录>\\browser-agent\\extension-auth.json",
  "pollMs": 1000,
  "graceMs": 400,
  "yieldTo": ["thorium.exe"]
}
```

网页模型桥使用独立的 `127.0.0.1:18774`，日常 Thorium `browser` 工具仍用 18773，两者不抢邀请。两台机器各用各自的本机配对令牌；模型桥配置将 `pageFreezeMs`、`freezeMs` 设为 0，避免暂停长回答、后台请求或轮询。登录与网站年龄确认仍由用户在极速中完成。

令牌只在内存里用。`yieldTo`：列出的进程（例如装着 Pi Background 扩展的 Thorium）在运行时桥暂停领邀请，关掉它后几秒内自动接手——两边同时领同一张邀请时，落败方的失败确认会把已经建立的连接标成失败。

智能体标签的显示（`showTabs`，默认 false）与省电设置（同一个文件里，括号内为默认值）：

| 键 | 作用 |
|---|---|
| `graceMs`（400） | 最后一条命令完成后保持可见多久，之后关焦点模拟并隐藏 |
| `freezeMs`（30000） | 隐藏后再过多久挂起页面（定时器、脚本全停），下一条命令到达时先恢复；每次挂起约有 150–400ms 的 CPU 尖峰，只在长间隔里划算；0 关闭 |
| `pageFreezeMs`（1000） | 隐藏后再过多久用 CDP 冻结页面（`Page.setWebLifecycleState frozen`，同 Chrome 冻结后台标签：脚本、定时器停住，网络照收），下一条命令前先解冻；比 `freezeMs` 的 TrySuspend 便宜；0 关闭 |
| `renderOnDemand`（false） | 按需出帧：只在截图、输入事件前唤醒；导航、读页面、快照在隐藏状态下执行（同后台标签），等待 Promise 的 evaluate 超过 `renderWaitMs`（200）仍未返回才唤醒 |
| `rasterScale`（1.0） | 在宿主里的光栅化比例：CSS 视口不变、像素更少，`srcset` 也会挑小图；0 跟随显示器 |
| `blockAutoplay`（true） | 媒体不自动播放：`play()` 像被浏览器自动播放策略拒绝一样返回 `NotAllowedError` |
| `blockImages`（false） | 不加载图片；用户点开这个标签看时不拦 |
| `blockedUrls`（内置清单） | 在智能体的 CDP 会话上用 `Network.setBlockedURLs` 拦截的网址模式，默认只含广告投放与统计上报；给 `[]` 关闭 |

## 安装

用 CI 运行包安装到当前用户（不需要管理员）：

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install.ps1 -Package <运行包里的 jisu-browser 目录> -ShortcutDir <快捷方式目录> -StartMenu -AgentTokenFile <Pi 的 extension-auth.json> -YieldTo thorium.exe
```

浏览器正在运行时更新（每次发版都是这种情况）：下载并解压 CI 产物，再

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\update-from-ci-package.ps1 -Package <解压后的目录> [-SetMediumLabel]
```

先把整个包按 `SHA256SUMS.txt` 核对完，再只换内容有变化的文件：旧文件备份到 `_历史版本\`（`<原名>.bak-<时间>-<标签>`，读回哈希），再用 File.Replace 换入，不结束任何进程，已开的窗口重启后才是新版本；播放器正在播放时整体放弃，任何一步失败都停下。有变化时在 `%LOCALAPPDATA%\JisuBrowser\update-<版本>-<提交>.json` 留回执；`-SetMediumLabel` 见上文（本机其余进程都是 High 时不要加）。

程序装到 `%LOCALAPPDATA%\Programs\JisuBrowser`，覆盖前旧程序、旧 `ntp\` 与媒体组件留在 `_历史版本\`；新写的智能体配置默认指向 18774；目标程序正在运行时脚本会停下，不会结束它。新写的智能体配置只包含 `broker`、`tokenFile`、`yieldTo`，省电项跟随程序默认值；已有配置默认保留，只有 `-ForceAgentConfig` 才备份并重写。

## 智能体 CPU 对比

`measure/agent-bench.mjs` 用 Pi 同一套 Playwright MCP 扩展模式（进程内测试 broker + relay，打 Pi 的两个补丁）在同一组站点上按「执行一步 → 等待」驱动浏览器；`measure/jobrun.cs` 把浏览器整棵进程树放进 Job Object 记账 CPU（已退出的渲染进程也算）。

最终程序 `d10c6f8`、默认省电设置的本机对照（13 个站点 × 导航、文本、快照、滚动，共 52 步）：

| 命令间隔 | Thorium CPU 秒 | 极速 CPU 秒 | Thorium / 极速 | CPU 减少 |
|---|---:|---:|---:|---:|
| 按 Pi 日志抽样的真实间隔（单次上限 120 秒） | 177.8 | 71.5 | 2.49× | 59.8% |
| 固定 10 秒 | 99.8 | 69.5 | 1.44× | 30.4% |

这些数字仅对应 `d10c6f8` 的无扩展基线，不代表当前带扩展、且关闭冻结的网页模型桥。它们是整棵进程树累计 CPU 时间，不是网页速度或瓦特实测；**整体 CPU 降到 1/3 的目标尚未达到**。真实间隔组的执行期 CPU 为 49.2 → 46.3 秒，间隙为 128.6 → 25.1 秒，收益主要来自等待时少运行。

两组都是实时网络单轮对照，测试期间有用户输入，不能当成稳定性能保证；两边均有一次导航超时，10 秒组 Thorium 还多一次固定标签协议错误，数字包含失败步骤。较早构建的空闲态结果不混入最终程序的整体成绩。

默认不禁图片、不启用按需出帧；禁图片会影响图像识别，按需出帧可能延长重型 SPA 初始化。默认禁自动播放只作用于智能体标签，媒体自动播放行为会改变。两边都用临时配置目录，窗口放在屏幕外不激活。

## 测量 G1 / G2

```
powershell -NoProfile -ExecutionPolicy Bypass -File measure\run-g1g2.ps1 -Exe <jisu-browser.exe> -OutDir <结果目录> [-Runs 20] [-Preheat] [-ShellArgs "--rt hw"]
```

外部计时复用可行性原型（不在本仓库）里 `jisu-probe.exe` 的 launch 模式（CreateProcess 前打点，WinEventHook 捕获窗口显示），用 `-Probe` 指定路径；内部时间线零点为进程创建时间。

- G1：`firstFramePresented`，首帧 EndDraw 后由后台线程 DwmFlush 等到 DWM 合成的时刻，≤ 70ms。
- G2：新标签页内容首帧，≤ 500ms，预热时 ≤ 300ms。每轮取较晚者：`ntpFirstFrameHost`（rAF 之后的下一个任务里回报、外壳收到的时刻，与可行性原型的 `webFirstFrameMs` 同口径）与 `ntpFcp`（Chromium 记录的首个内容帧呈现时刻）。
- `-WaitUserIdle <秒>`：每轮都等键鼠空闲满这么久再跑，有人在用机器时不弹测试窗口；`-AbortOnInput`：开跑后一有输入就整批放弃（采 ETW 用）。
